我会拿你亲手跑过的草稿修改请求，讲清这三层各接到什么，又把什么交给下一层。

**Controller 接 HTTP 请求，Service 处理业务规则，Repository 负责和数据库打交道。** 它们通过调用方法把数据往下传，再把结果逐层传回来。

拿你亲手验证过的 **用户 `1` 把草稿 `13` 改成 `6500` 分**举例：

```text
curl 发 PUT 请求
  → DraftController 取出项目 ID、草稿 ID、登录用户 ID、用途和金额
  → DraftService 校验参数
  → DraftRepository 执行 UPDATE
  → MySQL 返回更新行数
  → Repository 把行数交给 Service
  → Service 把行数交给 Controller
  → Controller 回复 HTTP 204 或 404
```

| 这一层 | 在你的项目里负责什么 |
| --- | --- |
| **Controller** | 听得懂 HTTP。它从 URL 取项目 `1` 和草稿 `13`，从服务端 Session 取登录用户 `1`，从请求体取用途和金额。拿到结果后，它决定回什么状态码。 |
| **Service** | 负责业务规则。比如检查草稿 ID 是否为正数、金额是否为负。金额是 `-1` 时，Service 会抛出异常，Controller 把异常转成 `400`。此时还没调用 Repository。 |
