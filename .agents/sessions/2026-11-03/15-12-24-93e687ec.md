### 3. 查看状态并暂存
先指导学员执行 git status：status 用于查看当前分支和文件状态，不会提交内容。首次结果显示学习计划和本会话日志目录属于 Untracked files，即新文件尚未纳入跟踪。

之后学员亲自执行：

```bash

```

关键解释：add 把指定文件当时的内容放入暂存区，选择下一次提交要包含什么；暂存不等于提交，也不会推送到 GitHub。指定文件路径便于控制范围，不把无关内容一起加入。执行成功通常没有输出，再用 git status 验证。

验证依据：学员截图中，Changes to be committed 下显示 new file: docs/learning-plan.md。agent 只读 Git 检查也显示 A docs/learning-plan.md；会话日志目录仍为未跟踪。已确认本任务的学习计划暂存由学员亲自完成。

## 八、任务与日志的提交机制
学员请求原话：“帮我详细解释任务和日志的提交机制”。此前学员确认日志随任务分支保存，不需要每轮提交，并询问成果和日志是否必须分开提交。

以下保留本轮实质教学摘要，不是完整答复逐字副本：
- 任务成果和会话日志都是仓库普通文件，目录用途不同，但适用相同 Git 流程。分支不是目录，同一任务分支可以同时保存 docs 和 .agents 下的文件。
- 工作区保存当前编辑内容；暂存区保存 add 时选定的文件版本；commit 把暂存内容记入本地分支历史；push 才将提交发送到远程同名分支；PR 请求将任务分支合入自己的主分支。
- 本任务可将学习计划和对应日志放入同一次 commit，使用同一个 PR。较大任务也可以有多个清楚的阶段性 commit，在同一个任务分支和 PR 内推进，不是必须每个任务只有一次 commit。
- 日志持续更新，但不为每轮对话单独提交。add 后再次编辑文件时，后续修改尚未暂存；要包含最新版本，检查后需要再次 add。
- 已提交的日志后续仍可编辑；新内容跟随下一次合适的阶段提交。日志写入和内部记录动作不递归生成一轮，也不为记录每次提交额外无限提交。
- 切换前检查代码、日志和暂存状态；有未提交文件时先决定保留方式，未跟踪文件不能视为已在分支历史保存。切换后原日志不可见时查明来源并安全带回，不建空文件冒充续写。
